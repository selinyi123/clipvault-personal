## 4. 对五个项目的机会、风险和行动建议

### DPMS

沿现有真实执行系统增加 `ExecutionSession`，先只做观察、协作、审批和 handoff，不改变 real-run 安全链。

### Prompt Performance Engine

增加 environment snapshot + deterministic verifier；再做 BudgetSweep，测单位预算成功率，而不只是单一模型分数。

### KIS

增加 `ContextRef`，让经过 canonical/信任边界筛选的 KnowledgeCard 进入 Agent Session，而不是整个知识库直接注入 Prompt。

### ClipVault

当前最重要的不是继续加 AI feature，而是守住 local-first、Secret Guard 与瞬态敏感数据边界。未来 ContextEnvelope 可以预留：

```text
session_ref: optional
persistence_policy
sensitivity
origin
source_device
source_app
```

但 OTP、credential、secret 类必须强制：

```text
session_persist = forbidden
history_persist = forbidden
TTL = bounded
replay = forbidden/one-shot
```

如果未来接入 Agent Session，ClipVault 应成为 **可信本地上下文入口**，而不是把剪贴板自动灌入 Agent 长期 memory。

### Binggo

先扩只读 MCP 与 action preview，不直接授权真实参与动作。

## 5. 今天最值得执行的 5 个动作

1. DPMS：定义 `ExecutionSession v0.1`。
2. Prompt：做 environment snapshot + deterministic verifier PoC。
3. KIS：定义 `ContextRef`。
4. ClipVault：在协议草案中加入可选 `session_ref`，并明确 sensitive payload 永不随 session 持久化。
5. Binggo：限定下一阶段 MCP 为只读诊断与 action preview。

## 今日判断

今天最有价值的变化不是“Agent 更自治”，而是 Agent 执行开始成为多人可见、可预算、可审批、可交接的共享状态。

五个项目可逐渐共享：`ExecutionSession / ContextRef / ExecutionBudget / PolicyDecision / TrustContext / Artifact / Evidence`。ClipVault 在这套体系中最合理的位置不是 Agent memory，而是 **Local Trusted Context Transport**。
