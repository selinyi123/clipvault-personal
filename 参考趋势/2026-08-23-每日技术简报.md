# 每日技术简报｜2026-08-23

## 今日结论

今天最值得追踪的不是新模型，而是 Agent Runtime 的两个基础能力正在快速成熟：

1. **Runtime Event Log / durable authority**：执行日志不再只是观测数据，而开始成为 session、恢复、UI、上下文投影和审计的权威来源。
2. **Cost / cache / budget engineering**：缓存命中、cache write/read、token、tool-call 上限和 per-run spending 正逐渐成为 Agent 配置的一部分，而不是账单后的统计。

对 DPMS / PPE / KIS / ClipVault / Binggo 的共同启示是：下一阶段最值得共享的 primitive 不应继续扩成新的 Agent 协议，而应围绕 `ExecutionRecord / ContextRef / CostProfile / PolicyDecision / Evidence` 建模。

## 2. 今天最值得看的开源项目

### Apache Maka

GitHub： https://github.com/apache/maka

Maka 的核心思路是 **Log is the Runtime**。模型消息、Tool Call、Tool Result、permission decision、termination fact 进入 append-only Runtime Event Log；Session、UI、Context、Recovery 则是 projection。

尤其值得注意的是它明确区分 Context 与 History：compaction / pruning 可以减少下一次推理看到的内容，却不销毁执行证据。

### Vercel Labs / fx

GitHub： https://github.com/vercel-labs/fx

`fx` 是 Zig 写的极小型、可嵌入 coding-agent harness，支持 Skills、MCP、subagents，并提供 WASM 嵌入方向。近期 PR 集中在权限一致性、destructive action 审批、subagent 退休、认证所有权、goal tracking 和 MCP timeout。

### Windows AppContainer sandbox

Maka 0.1.11 加入 brokered Windows AppContainer sandbox 和更严格的 IPC/ACL。对 Windows 本地应用尤其值得跟踪，因为当前 Agent sandbox 生态仍明显偏 Linux。

## 3. 技术趋势与架构参考

### Context / History / Evidence 三层分离

```text
Evidence → 永久执行事实
History  → 可浏览交互
Context  → 当前 inference 的有限工作集
```

### 本地敏感上下文更适合“derived signal”而非“raw data everywhere”

ClipVault 如果未来接本地分类器或 Agent，控制面最好只获取：

```text
classification
sensitivity
origin
TTL
persistence decision
```

而不是默认把原始 secret 注入 Agent session。

### Windows 原生隔离值得提前研究

如果未来引入本地模型做 secret / OTP / content 分类，应把 classifier 视作潜在高权限处理器，而不是普通 UI helper。Windows AppContainer、低权限 broker、loopback-only IPC 等机制值得进入 threat model。

## 4. 对五个项目的建议

### DPMS

新增只读 `ExecutionRecord` projection，复用现有 event/audit/evidence，不改变 real-run authority。

### Prompt Performance Engine

新增 `CostProfile + CachePolicy`，做缓存布局 A/B、Budget Sweep 和 Context Layout Ablation。

### KIS

新增 `ContextSelection` artifact，记录一次 inference 实际使用的 card/revision/hash/trust state。

### ClipVault

今天没有足够强的新竞品信号支持扩大功能边界。当前最合理的动作仍然是**不扩产品面，补协议边界**。

建议未来 `ContextEnvelope` 至少预留：

```text
origin
source_app
source_device
content_hash
sensitivity
persistence_policy
session_ref
```

对于 OTP / credential / secret，坚持：

```text
history = forbidden
knowledge ingestion = forbidden
persistent session = forbidden
TTL = bounded
replay = one-shot / forbidden
```

机会：后续若做 Local Policy Agent，可在本机生成派生策略信号，再决定 sync / relay / persist / block。

风险：不要因为“Agent 可以帮忙分类”就让敏感 clipboard 默认进入模型上下文；即便模型本地运行，也应保持最小暴露和进程隔离。

### Binggo

增加只读 Run Trace / Action Preview，让 Agent 做 inspect → explain → preview，不直接控制真实互动动作。

## 今日最终判断

今天值得稳定下来的三个跨项目事实对象是：

```text
ExecutionRecord  → 这次执行发生了什么？
ContextSelection → 模型当时实际看到了什么？
CostProfile      → 为这次结果付出了多少资源？
```

ClipVault 在其中最合适的位置仍是可信本地 Context Source / Transport，而不是 Agent Runtime 或 Knowledge Store。保持这个边界，比继续添加 AI 功能更重要。
