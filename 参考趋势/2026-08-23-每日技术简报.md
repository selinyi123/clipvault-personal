## 3. 技术趋势与架构参考

### Credential Policy 正从 RBAC 升级成 Egress Policy

建议通用对象：

```text
CredentialGrant {
  credential_ref
  principal
  destination_hosts[]
  destination_device
  destination_app
  scope
  expires_at
  approval
}
```

### Context engineering 转向 progressive disclosure

短 map + 结构化知识 + exact revision + trust state + mechanical validation，比巨型 instruction/context 更稳定。

### Design Contract 必须有 Validator

完整 AI UI loop 应为：

```text
Design Contract → Implementation → Launch → Visual/Interaction Test → Validator → Evidence
```

## 4. 对五个项目的机会、风险和行动建议

### DPMS
保持现有幂等执行、状态回读、Evidence 与 real-run gate；可以增加 Goal/Budget Control Surface。优先设计 `CredentialGrant v0.1`，绑定平台 credential 的 adapter、destination、scope、TTL。

### Prompt Performance Engine
做 Context Topology Ablation：giant instructions vs short map+docs vs retrieved docs；再增加 unauthorized-destination policy benchmark，验证真正的 fail-closed。

### KIS
新增 `ContextBundle/ContextSelection`，记录 selected cards、exact revisions、trust states、selection reason 与 token budget，让每次 Agent run 可证明到底看了什么。

### ClipVault
当前 v1.6.0、local-first、Secret Guard、双端同步、IME 和 Personal Memory 边界无需扩大。今天最有价值的变化只应进入未来 OTP/secret contract：

```text
EphemeralCredentialEnvelope
├ source_device
├ source_app
├ destination_device
├ destination_app
├ sensitivity
├ ttl
├ one_shot=true
├ persistence=forbidden
└ history=forbidden
```

最重要的是 **destination-aware fail-closed**：即使设备已配对，也不能默认任何 secret 可以发到任何应用。OTP Relay 应绑定明确可信设备/客户端通道，必要时再绑定当前焦点应用或用户批准。

风险：不要因为本地 Agent 热点把 Secret Guard 交给云模型；原始 OTP/API key/password 的分类与路由策略优先保持确定性、本地和最小权限。

### Binggo
适合验证 Goal + Budget + inspect/explain/preview Control Surface；写动作继续走现有 deterministic executor、风控与状态回读。

## 最终判断

今天对 ClipVault 最重要的不是“做 Agent”，而是把现有 Secret Guard 再向传输边界推进：

> Secret 不仅要避免持久化，还必须在离开本机前知道它被允许去哪里。

跨项目建议共享：`ExecutionRecord / ContextSelection / CostProfile / PolicyDecision / TrustContext / CredentialGrant / Evidence`。
